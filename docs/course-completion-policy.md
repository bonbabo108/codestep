# CodeStep：講座最終課題の完成基準・作業を増やさないルール

更新：2026-10-21。**最優先の本人判断**（従来から繰り返し表明、2026-10-21再確認）。作業状態は別の `HANDOFF.md`、安全な本番反映手順は `docs/release-readiness.md` で管理する。本書を、新機能要求や承認権限の根拠にしない。

## 1. 目的と完成線（本人の意思）

- **転職支援カリキュラムの最終課題として、CodeStepを必要十分な状態に完成・提出し、評価/ロールプレイで説明できること。**
- 本格商用サービスの構築・不特定多数向け運営・最高得点の全取得は目的ではない。
- PR→mainマージ→Production URLで実際に操作できる状態を目指す。ただし **合格条件と安全な公開条件は別**。未達の機能は正直に明示し、「動作未確認」を「完成」と報告しない。
- 制作時間、本人の負荷、AIトークン、課金、判断の往復を最小化。新機能を思いついただけで追加しない。
- 本書は「確認済みの本人方針」であり、AIが過去に提案した高機能化・一般公開向けSMTPを無条件で採用したものではない。

## 2. 着手前に必ず行う小さな判定

1. **評価表のどの項目**に役立つか？ 既存アプリ・デモ・README・画面証拠で満たせないか？
2. **しない場合**に、提出不能・セキュリティ問題・基礎操作不能が起きるか？ 単なる満点加点/装飾なら原則見送る。
3. **最小代替**は何か？ コード改修・サービス追加・本番設定より、既存成果の提示・説明・簡単な検証を優先。
4. **得られる評価上の効果と工数/リスク**を比較。加点の確証が薄い複雑な実装、運用設備、長時間の環境整備は原則延期。
5. 作業の実行が本当に必要な場合だけ取りかかる。本人には技術的な方法の逐次選択を求めず、安全に自律実行できる部分をまとめる。

**停止条件**：目的・評価項目・具体的な不具合のいずれでも説明できない追加作業は止める。これまでの作業量を理由に続行しない。本人に再度「最低限でよいか」と確認しない。

| 独自SMTP/ドメイン、OAuth、生成AI API、画像/音声入力、課金サービス、商用監視 | **原則見送り。** 特定の必須要件・安全上の理由が判明した場合だけ、費用/工数/代替と一緒に本人へ提案 |
| ローカルLLM・AI自己改善・新規開発ツール | **課題完成後の別案件** |
| 品質強化を目的とした追加テストや大規模リファクタ | 既存証拠で足りる範囲では再実行しない。重大な不具合・安全上必要な差分だけ |

メール認証について：**評価表の「メール・パスワード認証」と「OAuth最高評価」を区別**。講座課題のために独自SMTPを無条件で契約しない。ただし本番で実際にメール確認を必須とする仕様・課題要件なら、配信できない状態を成功扱いしない。Confirm email OFFなら「確認メールによる本人検証」は実装済みと主張しない。設定変更はリスク・代替を再確認する。
